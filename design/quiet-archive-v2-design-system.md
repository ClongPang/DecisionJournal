# 回看 · 静谧档案 2.0

**用途**：Android Compose 高保真改版依据
**设计关键词**：私密、可信、克制、时间感、纸张感
**不采用**：玻璃拟态、霓虹色、强渐变、数据驾驶舱、通用 Material 卡片堆叠

对应视觉板：[quiet-archive-v2-high-fidelity.png](./quiet-archive-v2-high-fidelity.png)

## 1. 视觉原则

1. **一页只讲一件事**：每页只保留一个视觉主角和一个主要行动。
2. **时间不是标签，是叙事**：日期、间隔、状态使用细线、色点和留白表达。
3. **纸张优先于容器**：内容由背景层次、排版和轻分隔组织；只有关键内容使用卡片。
4. **原始记录优先于统计**：洞察永远附带来源范围，不能像效率软件的 KPI。

### 2.4 动效与触感

- 页面进入：`fadeIn + slideInVertically(12dp)`，180ms，`FastOutSlowIn`。
- 卡片点击：缩放至 0.985，100ms；禁止明显弹跳。
- 保存成功：CTA 变为苔藓绿并显示“已保存”900ms，再导航。
- 删除与错误：不使用震动式持续动画；仅使用色彩、文案和清晰的二次确认。

## 3. 组件规范

### 顶部栏

- 主页面没有传统 AppBar 阴影；品牌与日期左对齐，右侧只保留一个低干扰更多入口。
- 子页面返回按钮为 40dp 无填充触控区，标题始终居中或与内容左缘对齐，二选一，不混用。

### 主叙事卡

- 首页仅一张，使用 `accentMist`，圆角 `radiusHero`。
- 内容顺序：状态/日期 → 问题 → 时间关系 → 极淡水墨地景。
- 地景只位于卡片底部 28% 区域，透明度低，不承载文字和操作。

### 内容卡与行项目

- 内容卡只用于需要独立阅读的文字、复盘对照、寄语。
- 设置项、日期、筛选器使用 `surface` 行项目和 `hairline`，不再额外包卡。
- 禁止“卡片内卡片内输入框”的三层容器结构。

### 选择卡

- 选中项：左侧 3dp `accentInk` 竖线，浅雾蓝背景，右侧单一确认符号。
- 利好与担忧采用小色点和文字，不滥用胶囊标签。
- 拖动/排序仅在编辑状态显示，弱化为右侧图标。

### 按钮与底部导航

- 主 CTA 为全宽 56dp，墨蓝实色，白字；一个页面最多一个。
- 次级操作使用文本按钮或 1dp 边框，禁止与主 CTA 抢色。
- 底部导航使用暖纸背景与上分隔线；选中项为墨蓝图标 + 2dp 短线，避免厚重药丸底座。

## 4. 六页高保真版式

### A. 今天 / 首页

```text
回看                                      ···
8月4日，星期二

给自己一点时间

┌────────────────────────────────────┐
│ ◷  等待回看 · 还有 12 天             │
│                                    │
│ 要不要接受那份工作？                 │
│                                    │
│ 决定于 8月3日                         │
│ 〔极淡水墨山线与芦苇，仅在底部〕       │
└────────────────────────────────────┘

                 [ ✎ 记录一个决定 ]
今天              决定                我的
```

### B. 新的决定 / 书写页

- 标题使用 `pageTitle`，进度在标题下以细线和“01 / 03”表达。
- 问题是无外框大文本输入；背景是折叠的次级编辑区。
- 底部 CTA 固定，但使用半透明 `canvas` 背板与上边线，不做悬浮大块。

### C. 选择比较 / 决策页

- 顶部为“我会选择什么？”和简短说明。
- 方案卡并列纵向排列；被选中方案由左边色线而非整块高饱和底色标识。
- 每个方案仅显示最重要的 2 条利好、2 条担忧；其余内容展开查看。

### D. 写给未来的自己 / 信笺页

- `sandMist` 大面积纸张，带极淡横线；文字区域保持 24dp 内边距。
- 字数统计贴近右下角，日期行独立置于信笺下方。
- 将“保存”定义为“封存这段判断”，更有产品仪式感。

### E. 决策详情 / 当时与后来

- 顶部主卡呈现原问题和状态。
- 下方采用两段而非多张同质卡：`那时`（选择、在意、担忧）与 `后来`（实际结果、满意度）。
- “预期 / 实际”用两列轻卡直接对照；复盘历史沿细时间线向下延伸。

### F. 我的决定 / 私人档案

- 三个概览卡只显示一个数字或短词：已回看、反复在意、等待答案。
- 时间线使用日期、色点、问题、状态四项；每行高度控制在 72–84dp。
- 洞察文案必须附“来自 N 条记录”，以小号 `meta` 放置在底部。

## 5. Compose 落地映射

1. 在 `Color.kt` 替换现有语义不清的色值为上述 token；页面禁止继续直接定义色值。
2. 在 `Theme.kt` 增加 `JournalSpacing`、`JournalElevation`、完整 Typography，并接入两套中文字体资源。
3. 重写 `SoftSurfaceCard` 为 `NarrativeCard`、`ContentCard`、`ArchiveRow` 三类组件，避免一个万能卡片覆盖所有场景。
4. 先改首页、详情与底部导航，形成可见的品牌变化；再改创建向导和时间线。
5. 每个页面以 360dp、411dp 和 1.3 倍系统字体进行截图验收。

## 6. 验收标准

- 用户在 3 秒内能辨识该产品是“记录与回看决定”，而不是待办或数据看板。
- 每页只有一个视觉主角和一个主 CTA。
- 用户文字的视觉优先级高于装饰、图标和统计数字。
- 卡片数量较当前实现显著减少，但信息层级更清楚。
- 所有状态在低对比暖色背景下仍达到可读性与触控可用性要求。
