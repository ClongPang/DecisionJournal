# 四角色页面与模块体验评审（2026-08-05）

参与角色：产品经理、UI 设计师、资深用户、首席开发师。

## 评审范围与证据

- 页面：今天、全部决定、我的档案、新建/编辑三步、详情、复盘、通知权限与所有空缺/加载/删除确认状态。
- 数据：在一台 Android 16 真机上通过 Debug 专用 Intent 显式预热 54 条跨日期记录（含到期、未来、无日期、多次复盘和未选最终方案）。
- 自动化基线：`testDebugUnitTest` 与 `connectedDebugAndroidTest`；后者当前覆盖 Room、校验、提醒调度和统计。

## 共同决策

| 优先级 | 决策 | 理由 | 本轮状态 |
|---|---|---|---|
| P0 | 首页和档案使用 Loading / Empty / Content / Error，而非用空列表充当加载完成 | 防止把正在读取误显示为“没有记录” | 已实施 |
| P0 | 选择“今天回看”时明确这是立即待回看，不承诺系统通知 | 日期存为当天 00:00，不能可靠安排未来通知 | 已实施 |
| P0 | 补齐暖纸主题的语义色、错误 live region、单选语义与 48dp 筛选触控区 | 保证视觉一致与读屏/触控可用 | 已实施 |
| P0 | 保存后在详情显示短暂的成功反馈；提醒失败仍单独提示 | 区分内容保存与系统提醒状态 | 已实施 |
| P1 | “决定”和“我的”提供常驻“新建”入口 | 长期用户不必返回首页才能继续记录 | 已实施 |
| P1 | 我的档案仅在至少 3 条证据时显示“最常在意”；否则解释样本不足 | 避免把单条记录包装成结论 | 已实施 |
| P1 | 复盘卡显示距决定/上次回看的时间，并按真实历史次数编号 | 强化“时间后再回看”的产品价值 | 已实施 |
| P1 | 搜索扩展到候选项和复盘内容，并显示命中来源 | 长期档案应能按方案和结果找回 | 已覆盖检索范围；命中来源展示后续迭代 |
| P1 | 首页展示多个到期项的队列摘要 | 降低遗漏多条待回看的风险 | 后续迭代 |
| P2 | 创建高级字段折叠、详情降低卡片密度、日期选择器主题化 | 降低填写负担并进一步贴近 Quiet Archive 设计系统 | 后续迭代 |

## 明确不在本期范围

账号、云同步、远程 AI、自动决策、社交协作、复杂图表均不纳入当前本地 MVP；长期数据导出/导入作为下一阶段独立需求评估。

## 真机验证清单

1. 空库、预热库、冷启动、重启、离线。
2. 创建最小路径、候选项编辑/排序/删除、今天与未来回看日期、未保存退出。
3. 状态和时间筛选、关键词搜索、分页、档案洞察的 0/1/2/3 条证据边界。
4. 详情的原始内容、多次复盘间隔、编辑后历史保留、删除确认。
5. 复盘的四种预期匹配、满意度、下一次回看和不再提醒。
6. 通知授权、拒绝、系统频道关闭，以及 360dp、1.3 倍字体、键盘和系统深色状态栏。
