# 产品需求文档：通过决策认识自己

**产品名称**：回看 · Decision Journal
**文档版本**：1.0
**日期**：2026-08-04
**文档状态**：产品方向与下一阶段规划
**质量评估**：92/100

---

## 1. 执行摘要

“回看”是一款本地优先的个人决策记录与复盘产品。用户在面对重要决定时，记录自己当下的选择、依据、在意的事情、担忧和预期；在未来回看实际结果，并通过长期积累发现自己的价值排序、决策风格、判断偏差和情绪模式。

产品的最终价值不是帮助用户找到一个抽象意义上的“正确答案”，而是帮助用户看见：自己是如何做决定的，什么事情真正重要，哪些判断经常被现实验证，哪些担忧经常被高估，以及自己正在变成怎样的人。

产品应保持本地、离线、低打扰和尊重用户自主性的特点。所有洞察必须来源于用户自己的记录，并以可追溯、可修正、非评判的方式呈现。产品不替用户做决定，不给用户贴固定人格标签，也不将统计结果伪装成心理诊断。

## 2. 产品定位

### 2.1 一句话定位

> 看见自己是如何做决定的。

### 2.2 核心价值主张

当用户面对重要决定时，“回看”帮助用户保留当时的真实想法；当事情发展一段时间后，产品帮助用户比较预期与现实；当记录积累后，产品帮助用户发现个人模式，从而更加了解自己，并做出更适合自己的选择。

### 2.3 产品价值闭环

```text
记录决定
  ↓
保留当时的依据、情绪和预期
  ↓
在合适时间回看结果
  ↓
比较预期与现实
  ↓
发现重复出现的主题与模式
  ↓
形成对自己的理解
  ↓
影响下一次决定
```

### 2.4 产品原则

1. **先保存真实，再产生洞察**：洞察不能覆盖或改写用户当时的原始记录。
2. **描述模式，不定义用户**：使用“最近几次记录显示……”而不是“你就是……”。
3. **帮助理解，不替用户判断**：系统可以展示信息和关联，但不输出“应该选择什么”。
4. **让记录足够轻，让回看足够有价值**：第一次记录应低门槛，复盘和长期洞察是留存核心。
5. **隐私是核心体验的一部分**：默认离线和本地存储，不要求账号，不上传个人决定。
6. **允许矛盾和变化**：用户的价值排序会变化，产品不应强行生成稳定人格结论。

## 3. 当前产品现状与问题

### 3.1 当前已具备能力

- Android 原生应用，Kotlin、Jetpack Compose、Room、Hilt、Navigation、WorkManager。
- 本地创建、编辑、查看和删除决策。
- 记录候选选项、最终选择、背景、利好、担忧和写给未来的自己的话。
- 设置复盘日期和本地提醒。
- 记录一次或多次复盘结果与 1～5 满意度。
- 首页、全部决定、我的决定、详情和复盘页面。
- 浅色、克制、低打扰的视觉方向。

### 3.2 当前核心体验问题

#### 问题一：产品价值还停留在“记录”

用户可以保存一条决定，但保存后没有立即感受到“这对认识自己有什么帮助”。首页和详情页更多是内容展示，长期价值尚未被明确表达。

#### 问题二：创建流程对新用户偏重

当前流程包含背景、在意事项、担忧事项、候选项及其利好和担忧、未来寄语等字段。完整，但容易让普通用户感觉是在填写一份表格。

#### 问题三：复盘缺少“预期—现实”的比较

当前复盘可以记录结果和满意度，但还没有系统地要求用户回看当时的预期，也没有帮助用户总结判断准确与偏差之处。

#### 问题四：历史记录还没有转化为自我洞察

“我的”页面目前更接近数据概览和时间线，尚未回答用户最关心的长期问题：我在意什么、害怕什么、如何判断、是否正在改变。

#### 问题五：页面职责需要进一步拉开

“决定”与“我的”都展示决策时间线。后续应明确：“决定”用于管理和检索，“认识自己”用于理解长期模式。

## 4. 用户与使用场景

### 4.1 核心用户：有自我反思意识的成年人

- 年龄不作为硬性限制，主要是学生、职场人、自由职业者和处于人生转折期的人。
- 愿意记录重要经历，但不希望使用复杂的效率工具或公开社交平台。
- 关心“我真正想要什么”，但常常只能在结果发生后才重新理解自己的选择。
- 对隐私敏感，希望个人记录保留在自己的设备上。

### 4.2 资深用户：持续进行个人复盘的人

- 已经使用日记、Notion、备忘录或表格记录决策。
- 关注价值排序、风险判断、预期准确度和长期变化。
- 愿意为高质量回顾投入时间，但不愿每次重复录入大量基础信息。
- 需要搜索、标签、模板、关联历史决定和可追溯的洞察依据。

### 4.3 关键使用场景

1. **重大决定前**：换工作、搬家、关系选择、重大消费、长期项目。
2. **无法判断时**：用户在多个选项之间反复犹豫，需要把隐含的在意和担忧说清楚。
3. **结果发生后**：用户想知道决定是否符合预期，而不是只凭当下情绪评价。
4. **长期回顾时**：用户想知道自己过去一段时间真正关注什么、是否发生变化。
5. **相似问题再次出现时**：用户希望参考过去类似决定，而不是从零开始思考。

## 5. 用户目标与用户故事

### 5.1 记录决定

**作为**正在面对重要选择的用户，
**我希望**快速记录问题、选项和当时的想法，
**以便**未来能知道自己当时为什么这样选。

验收标准：

- 问题、至少一个候选选项可以在低摩擦流程中完成。
- 背景、在意事项、担忧、未来寄语均可跳过。
- 用户能够记录当时的预期结果和信心程度。
- 保存后原始内容可完整查看，不能被后续复盘覆盖。

### 5.2 回看结果

**作为**已经到达复盘时间的用户，
**我希望**同时看到当时的记录和现在的结果，
**以便**比较预期与现实。

验收标准：

- 复盘页明确展示原始问题、最终选择、当时预期和未来寄语。
- 用户能够记录实际结果、满意度和与预期的差异。
- 用户可以填写“判断准确的地方”“没想到的地方”和“下次会怎么做”。
- 复盘后原始记录仍然可见，新增内容按时间追加。

### 5.3 认识自己的模式

**作为**已经积累多条决策记录的用户，
**我希望**看到反复出现的主题与变化，
**以便**更加了解自己的价值排序和决策方式。

验收标准：

- 每一条洞察都能追溯到具体记录。
- 洞察使用概率、次数、时间范围等依据，不输出无依据的绝对判断。
- 用户可以隐藏、纠正或标记“不符合我的理解”的洞察。
- 数据不足时明确显示“记录还不够”，不强行生成结论。

### 5.4 再次做相似决定

**作为**正在面对类似问题的用户，
**我希望**找到过去相关的决定，
**以便**参考过去的真实经验。

验收标准：

- 可以按主题、状态、日期和关键词检索。
- 相似记录展示原始决定、结果和用户自己的复盘，不自动给出建议。
- 新决定可以从历史模板或相似记录开始，但必须由用户主动确认内容。

## 7. 核心功能需求

### 7.1 首页：今天

#### 目标

让用户一打开应用就知道：现在有哪些事情值得回看，以及今天是否适合记录一个新的决定。

#### 功能要求

- 展示品牌名“回看”、当前日期和低打扰问候。
- 有待复盘内容时，按紧急程度展示待复盘列表，而不是只展示一条。
- 没有待复盘但有历史时，展示最近决定和最近一次回看摘要。
- 无任何数据时，展示产品价值解释和创建入口。
- 主按钮支持“记录一个决定”。
- 首页不展示未经用户主动确认的评价性结论。

#### 建议文案

- 空状态：`把一个正在想的决定留下来，未来的你会回来看看。`
- 待复盘：`有几件事，到了回看的时候。`
- 最近记录：`最近，你曾经认真想过这些事。`

### 7.2 创建决定：轻量模式与深度模式

#### 轻量模式

适用于第一次使用或低重要度决定，只要求：

- 我在决定什么？
- 有哪些选择？
- 我倾向哪个选择？
- 什么时候回看？

整个流程目标控制在 30～60 秒内。

#### 深度模式

适用于高重要度决定，支持：

- 背景与限制条件；
- 我在意的事情；
- 我担心的事情；
- 每个选项的收益和风险；
- 预期结果；
- 判断信心 1～5；
- 写给未来自己的话；
- 决策主题和重要程度。

用户可以随时从轻量模式补充为深度记录。

#### 创建流程

1. 决定问题；
2. 候选选项与最终倾向；
3. 当时的依据与预期；
4. 复盘日期；
5. 保存并进入详情。

所有非必要字段均可跳过。保存期间按钮禁用，避免重复创建。

### 7.3 复盘：未来再看

复盘是产品的核心价值节点，页面需要分为三层：

#### 第一层：回到当时

- 当时的问题；
- 当时选择的选项；
- 当时在意的事；
- 当时担心的事；
- 当时的预期；
- 当时的信心；
- 写给未来自己的话。

#### 第二层：记录现在

- 实际发生了什么；
- 当前满意度 1～5；
- 实际结果与预期是否一致；
- 哪些地方比预期好或差。

#### 第三层：带走一点什么

- 我判断准确的地方；
- 我没有想到的地方；
- 下次遇到类似问题，我会注意什么；
- 是否继续设置下一次回看日期。

复盘必须追加保存，不得修改原始决定。一次决定可以有多次复盘。

### 7.4 决定详情

详情页分为两个信息区：

- **当时的决定**：原始问题、背景、选项、选择、依据、担忧、预期和未来寄语。
- **后来发生了什么**：所有复盘记录、满意度、预期差异和后续行动。

提供编辑、继续复盘、设置下一次回看和删除操作。删除必须二次确认，并级联删除关联数据和提醒。

### 7.5 决定管理

支持：

- 全文搜索；
- 按状态筛选：待复盘、已回看、未设置日期；
- 按主题筛选；
- 按重要程度筛选；
- 按创建日期和最近回看日期排序；
- 从详情页重新发起复盘。

### 7.6 认识自己

这是产品的长期价值页面，分阶段建设。

#### 第一阶段：可追溯概览

- 最近记录最多的价值主题；
- 高频担忧主题；
- 各类决定的数量；
- 待复盘和已回看数量；
- 平均满意度及变化；
- 最近一条值得回看的记录。

#### 第二阶段：个人模式

- 你最近反复在意什么；
- 哪些担忧经常出现；
- 哪类决定最容易让你犹豫；
- 哪类预期最容易落空；
- 哪些决定后来满意度较高；
- 近三个月关注重点发生了什么变化。

#### 第三阶段：预期与现实

- 预期结果与实际结果的差异；
- 判断信心与实际满意度的关系；
- 高估风险或低估收益的主题；
- 相似决定之间的结果对比。

洞察展示规则：

- 至少有 3 条相关记录才生成主题性洞察；
- 每条洞察必须显示数据范围和样本数量；
- 每条洞察提供“查看相关记录”；
- 使用“可能、最近、经常出现”等谨慎表达；
- 不使用人格诊断、心理诊断或能力评分。

## 8. 数据模型扩展

现有模型可继续扩展为：

```text
Decision {
  id: Long
  question: String
  context: String?
  importance: Int?              // 1..5，可选
  category: String?             // 工作、关系、生活、消费等
  tags: List<String>
  benefits: List<String>
  concerns: List<String>
  expectedOutcome: String?
  confidence: Int?              // 1..5，可选
  futureNote: String?
  createdAt: Instant
  updatedAt: Instant
  reviewDate: LocalDate?
  status: ACTIVE | REVIEWED | ARCHIVED
  selectedChoiceId: Long?
}

Review {
  id: Long
  decisionId: Long
  createdAt: Instant
  actualOutcome: String
  satisfaction: Int?
  expectationMatch: EXPECTED | BETTER | WORSE | UNCLEAR
  accurateJudgment: String?
  unexpectedFinding: String?
  nextTimeNote: String?
  nextReviewDate: LocalDate?
}
```

数据设计要求：

- 所有字段均本地保存；
- 原始决定和复盘记录分离保存；
- 洞察由原始数据动态计算或生成缓存，不反向覆盖原始数据；
- 支持数据库迁移；
- 删除决定时级联删除选项、复盘、标签关联和提醒；
- 最终选择必须引用真实 Choice ID，不使用列表索引代替。

## 9. 隐私与安全

- MVP 不要求注册、登录、手机号或邮箱。
- 不上传决定、复盘、设备标识或洞察数据。
- 无网络时必须完成创建、查看、编辑、删除和复盘。
- 导出必须由用户主动触发，并明确展示导出内容和保存位置。
- 生物识别锁作为后续功能，开启后应覆盖应用进入和后台恢复场景。
- 若未来加入本地 AI，应默认关闭，并在调用前明确说明处理范围。
- 洞察不得作为医疗、心理或职业决策建议。

## 10. 分阶段路线图

### Phase 0：当前 MVP 闭环修正

目标：保证“创建—提醒—复盘—再次回看”可靠完成。

- 修正选项 ID 与最终选择的关联；
- 首页展示多个待复盘事项；
- 完善空、加载、错误、保存中和成功状态；
- 创建流程允许跳过非必要字段；
- 复盘页展示原始预期并增加预期差异；
- 明确已回看、待复盘和继续回看的状态；
- 完善重复保存、日期变更和级联删除测试。

### Phase 1：认识自己 v1

目标：从统计记录升级为有依据的自我观察。

- 主题和标签；
- 重要程度与判断信心；
- “认识自己”页面；
- 高频在意事项与担忧事项；
- 满意度趋势；
- 每条洞察关联原始记录；
- 洞察不足时显示数据不足提示。

### Phase 2：认识自己 v2

目标：帮助用户发现判断模式。

- 预期与现实对比；
- 相似决定关联；
- 价值主题随时间变化；
- 常见犹豫类型；
- 决策模板；
- 高级搜索与筛选；
- Markdown、JSON、PDF 主动导出。

### Phase 3：本地智能辅助

目标：降低整理成本，不替用户做决定。

- 本地总结历史记录；
- 主动选择记录后生成主题摘要；
- 帮助用户发现矛盾或重复出现的内容；
- 生成可编辑的复盘问题；
- 所有 AI 内容必须标明“这是基于已有记录的辅助整理”，并允许用户拒绝或删除。

## 11. 成功指标

### 核心指标

**复盘完成率**：设置复盘日期的决定中，最终完成至少一次复盘的比例。
首期目标：≥ 35%。

**二次使用率**：首次创建决定后 30 天内再次打开应用的用户比例。
首期目标：≥ 40%。

**洞察触达率**：拥有至少 5 条记录的用户中，打开“认识自己”页面的比例。
目标：≥ 50%。

**洞察可追溯率**：用户查看洞察后进入相关原始记录的比例。
目标：≥ 20%。

### 体验指标

- 首次创建决定完成时间：中位数 ≤ 2 分钟；
- 轻量记录中途放弃率：≤ 30%；
- 复盘页面保存成功率：≥ 95%；
- 删除、提醒、编辑等关键操作错误率：≤ 1%；
- 用户对“更了解自己”的主观评分：平均 ≥ 4/5。

### 质量指标

- 决策和复盘数据不丢失；
- 所有洞察都能查看依据记录；
- 离线核心操作成功；
- 数据层和业务逻辑覆盖率目标 ≥ 80%；
- 支持 1,000 条决策记录时列表仍保持可交互。

## 12. 非目标与边界

当前及近期版本不做：

- 自动告诉用户应该选择什么；
- 用算法给用户打人格或决策能力分数；
- 心理诊断、情绪诊断或职业诊断；
- 社交排名、公开分享和多人协作；
- 强制用户完成完整问卷；
- 在没有足够数据时生成确定性洞察；
- 依赖云端账号才能使用核心功能。

## 13. 关键验收标准

- [ ] 用户可在 60 秒左右完成一条轻量决定记录。
- [ ] 用户可在记录中保存问题、选项、倾向选择、预期和复盘日期。
- [ ] 原始决定内容在复盘后仍保持不变并可查看。
- [ ] 复盘页同时展示当时记录和当前结果。
- [ ] 用户可记录预期与现实的差异，以及下次会注意什么。
- [ ] 一个决定支持多次复盘，并按时间倒序展示。
- [ ] 首页能展示多个待复盘决定并支持优先处理。
- [ ] “认识自己”页面只显示有数据依据的观察。
- [ ] 每条洞察可跳转到相关原始记录。
- [ ] 数据不足时不生成强结论。
- [ ] 用户可以修正、隐藏或删除不认同的洞察。
- [ ] 应用全程支持离线使用。
- [ ] 数据不上传远程服务器。
- [ ] 关键提醒、删除、编辑和数据库迁移均有测试覆盖。

## 14. 待验证假设

1. 用户是否愿意在做决定之前记录，而不是只在结果发生后记录。
2. 用户更重视“看见自己的模式”，还是更重视“复盘某一次具体决定”。
3. 轻量记录是否足以推动用户完成第一次复盘。
4. 哪些主题分类最符合用户自然语言，而不是产品预设分类。
5. 用户是否信任基于 3～5 条记录生成的初步洞察。
6. “预期—现实”比较是否比单纯满意度更能促使用户持续使用。
7. 用户愿意接受多大程度的本地智能整理。

### 建议验证方式

- 访谈 8～12 名有日记或复盘习惯的用户；
- 观察 5 名新用户完成首次记录和复盘；
- 对轻量流程与深度流程进行可用性对比；
- 使用模拟数据验证洞察是否易懂、是否感到被贴标签；
- 在不上传内容的前提下，仅记录匿名使用事件：创建、复盘、查看洞察和返回原始记录。

## 15. 最终产品判断

“回看”不应该成为一个记录越来越多、但用户越来越不愿意打开的资料库。它必须围绕一个持续发生的变化来设计：

> 用户在每一次回看之后，都比之前更清楚自己在意什么、害怕什么，以及自己是如何成为现在这个自己的。

因此，产品未来所有功能都应回答一个问题：

> 这个功能是否帮助用户更准确、更温和、更有依据地了解自己？

如果答案是否定的，即使功能看起来复杂或智能，也不应进入核心产品。
